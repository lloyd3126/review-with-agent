# 文件檢視工作台

使用專案已寫好的 `workbench/` Next.js 應用，根目錄由本 skill 所在的專案推定。使用者下載的是整個專案，不需要重新產生網站。工具使用 Node.js 20.9 以上、npm 與 Python 3。介面採官方 Next.js 起始專案的黑白外觀與 Geist 字體，使用原生表單及對話視窗，不使用 Bootstrap 或彩色自訂佈景。PDF 顯示和文字層套件經 CDN 載入。

新增頁面及檢視功能時擴充現有 `workbench/src/`，依 `app`、`components`、`hooks`、`lib/client` 和 `lib/server` 分層，保留既有資料結構及操作流程，不另外搭建整套網站。

工作台上方按鈕依序為「上傳文件」、文件下拉選單、「上傳新版」與「刪除文件」。

## 開始與重開

1. 先確認專案根目錄與 `workbench/package.json`、`workbench/src/app/page.js` 存在。環境提供 `load_workspace_dependencies` 時，先取得可用的 Node.js 與 Python 路徑。否則檢查本機已有的環境，缺少時由 Agent 從官方來源準備至專案的 `.runtime/`，不要把安裝指令交給使用者操作。
2. 用可用 Node.js 執行 `scripts/workbench.mjs start --project-root 專案絕對路徑 --python Python絕對路徑`。腳本按需安裝鎖定依賴及建置既有網站。首次可能需要較久，持續追蹤執行到完成。`reopen` 也可使用，兩者會優先重用經健康檢查確認屬於此專案的服務，程式更新時重新準備並啟動。僅看到程序存在不代表工作台可用。
3. 讀取輸出的 `ready`、`url` 和 `projectRoot`。在內建瀏覽器開啟該網址，已有相同工作台分頁時重用，確認文件列表及文件預覽或新專案的上傳入口實際可見，並且未停在整頁錯誤畫面。正常介面不顯示「工作台已就緒」。把分頁保留為交付結果。
4. 若使用者未看到頁面，提示「請展開 App 的側邊欄，切換到內建瀏覽器查看工作台」。不猜測未確認的按鈕或圖示名稱。
5. 新使用者引導上傳 PDF 文件，再把參考資料交給 Agent 加入該文件，在對話中說「請檢視剛上傳的文件」即可。使用者修改原稿後，須自行匯出 PDF，再從同一份文件選擇「上傳新版」。Agent 直接讀取專案中的目前 PDF 與最新資料，不要求使用者手動轉貼檔案路徑或清單。已有文件時可繼續選用。單純說「開始」或「重開」只啟動並檢查工作台，不自動新增檢視建議或改動文件內容。
6. 使用者提供「複製錯誤訊息給 Agent」的內容時，以其中的網址、專案路徑、發生位置與錯誤時間診斷，並讀取 `.runtime/workbench.log`。修復服務後重新開啟並確認可操作，保留既有資料。若首次開啟就只有瀏覽器原生連線錯誤，先重新啟動服務，不能要求使用者點擊尚未載入的網頁按鈕。

啟動或重開不得清空資料、重新匯入既有文件、重設註解編號或覆寫原始檔。應用只監聽本機。讀取 [資料與指令](references/workspace.md) 處理文件與註解。

## 文件刪除與同步

使用者點擊「刪除文件」時，網站只開啟確認視窗，顯示目前選定文件的名稱與識別碼，說明會一併刪除該文件的 PDF、參考文件、註解與討論紀錄，不影響其他文件。視窗只提供「複製刪除提示」，不可直接從網站刪除。

使用者把刪除提示貼回 Agent 對話，才算授權刪除指定文件。一般檢視、開始、重開或清理畫面都不授權刪除或清空文件。收到提示後先核對識別碼與名稱確定目標正確，不需再次詢問確認，再使用：

```sh
node .agents/skills/lesson-review-workspace/scripts/workbench.mjs delete-document --lesson ID --confirm-delete
```

刪除提示為：

> 請刪除本專案工作台中的文件「NAME」（識別碼：ID）。我確認一併刪除這份文件的 PDF、參考文件、註解與討論紀錄。請保留其他文件。刪除後請確認這份文件已從工作台移除。

網站每 5 秒更新文件清單，刪除完成後自動移除已刪除文件。Agent 必要時讀取工作台畫面確認目標已消失。

## 關閉與恢復初始狀態

單純關閉使用 `scripts/workbench.mjs stop`，保留文件資料。使用者明確要求清空文件並恢復初始狀態時，使用 `scripts/workbench.mjs reset --confirm-reset`。這一個指令會核對並停止本專案伺服器，移除 `lessons/` 中的文件、參考資料、目前 PDF 與註解，保留程式、skills 和已準備的環境，不重新安裝或建置。沒有清空授權時不可加入確認旗標。

使用與啟動相同的 Node.js，必要時帶 `--project-root`。確認輸出包含 `reset: true`、`serverStopped: true`，並用 `status` 和 `list` 確認伺服器停止、文件清單為空。關閉舊工作台分頁，讓使用者之後說「開始」從空白工作台繼續。不要另外臨時寫刪檔與停止程序的腳本。遇到無法核對的程序，或 `lessons/`、`.runtime/` 本身是符號連結時先診斷，不改用直接刪除繞過檢查。

## 交付學生版本

需要交付乾淨專案時，使用 `scripts/workbench.mjs package`。它會產生 `dist/review-with-agent.zip`，只收集網站的 `src`、`tests`、`public`、依賴描述檔、README、AGENTS.md、skills 與必要設定，排除文件、執行環境、安裝套件、建置結果、Git 資料夾、環境檔與密鑰。封裝依實際檔案系統建立，不依賴 Git 追蹤狀態。完成後檢查壓縮檔內沒有 `lessons/` 或 `.runtime/`。

## 文件處理

新文件使用完整 UUID 作為識別碼。上傳後、重新檢視及討論問題的複製提示均包含固定的文件識別碼。Agent 優先以識別碼定位 `lessons/<id>/`，標題只供輔助辨識。

主要文件只接受 PDF，其他格式須由使用者先匯出為 PDF。參考資料不限格式。每份文件只保留 `lessons/<id>/document.pdf` 作為目前文件。使用者在原本的編輯工具修改原稿後匯出 PDF，再使用工作台的「上傳新版」替換同一份文件的 PDF。這個操作不保存被替換的舊 PDF。

更換流程先檢查 PDF。檢查成功後才替換 `document.pdf`，並更新 `lesson.json` 的 `format`、`originalName`、`pageCount` 與 `documentHash`。文件識別碼、標題與 `materials/` 參考資料保留。接著將 `review/annotations.json` 的 `annotations`、`history`、框選資料清空，將 `nextNumber` 重設為 1。即使再次上傳相同的 PDF，也執行相同清空。檢查失敗時保留原本的 PDF、文件資料、註解、討論記錄與參考資料。

更換完成後，畫面開啟「重新檢視文件」視窗並顯示可複製的重新檢視提示，不會自動呼叫 Agent。提示要求 Agent 以目前上傳的 PDF 與參考資料重新檢視，文件用途與背景可以沿用，但不要預設先前建議仍然成立。每個問題都要重新核對，只提出目前文件仍支持的問題，先指出問題與依據，再透過提問引導討論，不直接提供解法。這個流程只清空網站資料，不要求刪除 Agent 對話，也不要求完全獨立的討論脈絡。

提示文字為：

> 請先以視覺方式閱讀目前 PDF，並依格式閱讀這份文件的參考資料，再重新檢視文件。文件用途與背景可以沿用，但不要預設先前的建議仍然成立。每個問題都須重新核對，只提出目前文件仍支持的問題，避免為了延續先前討論而重複舊建議。先指出問題與依據，再透過提問引導我討論，不直接提供解法。

目前文件與 PDF 參考資料須先渲染並以視覺方式閱讀頁面，文字擷取僅供搜尋與定位。圖片直接查看，文字直接閱讀，其他格式使用相應工具。無法閱讀時說明限制，不假裝已核對。註解的 `page` 和 `rects` 使用顯示頁面的左上角相對座標。點擊註解時持續框出對應區域，`documentSha256` 或同等文件雜湊不符時不可把舊座標直接套到目前 PDF。

上傳資料屬該份文件的任務輸入。參考資料由 Agent 複製或新增至該份文件的 `materials/`，不限格式。網站只顯示清單，不提供管理按鈕、上傳、編輯、刪除或開啟操作。清單直接讀取非隱藏一般檔案，不需更新 `lesson.json`，不列出目錄或符號連結。保留檔名，不覆寫同名檔案。Agent 新增的整理文件須標明來源與用途，不當成使用者提供的標準。檢視以目前文件、使用者的用途與讀者，以及本次提供的參考資料為準。沒有正式規準時，不補造分數或能力分級。
